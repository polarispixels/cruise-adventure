# Cruise Adventure v0.1 — Design

Source spec: `docs/cruise-adventure-v0.1-spec.md` (Ryan's, Oct 29 2026). This document does not repeat it. It records the intent behind it, what was settled in conversation, and the builder's calls. Where the two disagree, this document wins.

## Intent

The only purpose of v0.1 is to **publish**: prove the pipeline end to end, from a Godot project in GitHub, to a CI build on every push, to a playable web build on GitHub Pages, to a signed APK installed on an Android tablet. The game can be extremely simple. Everything about polish comes in v0.2.

Success on day one: Ryan holds the tablet, installs the APK from the GitHub Releases page, opens "Cruise Adventure", drags the shirt into the suitcase, and gets the snap, chime, stars and checkmark. The same tagged build plays in a desktop browser at the Pages URL.

Eventual players are Jack (6) and Becca (4). The design rules (big targets, no reading, no failure states, unlimited retries) still apply, but nobody evaluates polish in v0.1.

## Goals

- The gameplay loop in the spec's Gameplay section, at its simplest.
- The CI workflow in the spec's Build and deploy section: web to Pages on push to `main`; signed APK as a workflow artifact on push and as a Release asset on `v*` tags.
- Tag `v0.1.0`, Release published, APK installs on the tablet.

## Non-goals

Everything in the spec's "Out of scope" list. Also: nice art, animation polish, sound design, tests beyond what proves the build works, and teaching Ryan the Godot editor.

## Anti-goals

- Over-building v0.1 (extra systems, frameworks, abstractions beyond the generic `draggable.gd` the spec asks for).
- Anything that makes later updates impossible: a lost or committed keystore, or an Android `version/code` that doesn't increase.
- Engine version drift between local verification and CI.

## Constraints and settled facts

- **Ryan has never used Godot.** Nothing in the workflow may require opening the Godot editor. All scenes (`.tscn`), scripts and `project.godot` are written as text by the builder.
- **Repo does not exist yet.** The builder creates `polarispixels/cruise-adventure` with `gh` (authenticated locally as `polarispixels`, a personal account, scopes `repo` and `workflow`). This directory is not yet a git repo.
- **Godot version: 4.7.2-stable** (latest stable as of today). CI image `barichello/godot-ci:4.7.2` (non-mono). This exact version is pinned everywhere.
- **Local tooling:** no Godot, Java or keytool installed in WSL. Docker Desktop is available. Python 3 with Pillow is available.
- The spec's hard rules stand: all visuals and sounds are files in `assets/`; the version lives only in `application/config/version`; never commit the keystore or passwords.

## Builder's calls (not agreed with Ryan; flagged for review)

1. **Local verification uses the CI Docker image.** The builder runs `barichello/godot-ci:4.7.2` locally to import and export the Web build before pushing, so CI failures are rare. No local Godot install.
2. **Placeholder art is generated by a Python + Pillow script** (`tools/make_placeholders.py`, committed), producing simple flat-colour shapes as the PNGs in `assets/art/`. Generated PNGs are committed. v0.2 replaces the PNGs with the kids' art, and the script then goes.
3. **The chime is synthesized** by a Python script into WAV and converted to `.ogg` (via ffmpeg inside a Docker container, or a pip package such as `soundfile`; builder's choice). The `.ogg` is committed.
4. **Keystore generation** runs `keytool` inside the godot-ci container (it ships a JDK). The keystore and a random password are written outside the repo, to `~/keystores/cruise-adventure/` in WSL. Secrets are set with `gh secret set`. Ryan is told plainly to back up that folder.
5. **Bigger than the spec's minimum for a 4-year-old:** the drop zone is the whole suitcase plus a margin, and the replay button is at least 200 px across the 1080 p base.
6. **Simplest possible celebration:** stars are a few `star.png` sprites tweened outward and faded. No particle systems.
7. **The version stamp reads `ProjectSettings.get_setting("application/config/version")`.** CI checks that a pushed `vX.Y.Z` tag matches that value and fails the release if it doesn't.
8. **Android package name `com.polarispixels.cruiseadventure`**, permanent from v0.1.0. The APK includes both `arm64-v8a` and `armeabi-v7a` so it installs on Fire tablets that run 32-bit apps on 64-bit chips. Min SDK stays at Godot's default, API 24 (Android 7).
9. **Fire tablets:** install instructions in the README mention Silk as the browser, since Chrome isn't on Fire OS.

## Answered by Ryan

- **Repo is public**, the same as `polarispixels/block-buddies`. That repo is public and serves Pages from `main` root. Cruise Adventure deploys Pages from GitHub Actions instead, because the web build is a CI output.
- **Tablet: Amazon Fire on Fire OS 8.3.3.8** (based on Android 11, API 30), above Godot's API 24 minimum. Install goes through Silk. Both CPU architectures ship (call 8).
- **New signing keystore.** Block Buddies has no Android build, workflows or secrets, so there's no key to reuse. Ryan left the choice to the builder.
